● Summary of Investigation

  I've identified the root cause of the 500 error on the /people page in PR #538:

  The Problem

  1. Dynamic Page Issue: The /people route has prerender = false, making it the only dynamic page route in production (other dynamic routes are API
  endpoints)
  2. Paraglide Runtime Bug: The error occurs in paraglide's runtime at two locations:
    - Line 147: extractLocaleFromUrl(window.location.href) in getLocale()
    - Line 300: localizeUrl(window.location.href, ...) in setLocale()
  3. Edge Environment Incompatibility: In Netlify's Edge Functions (which use Deno):
    - typeof window !== "undefined" returns true (window exists)
    - But window.location is undefined
    - The code only checks for window but not window.location
  4. First Request Failure: The error happens on the first request from a new client, but subsequent requests often work (likely due to caching or
  different code paths)

  Why This Affects Only Dynamic Pages

  - Static pages are pre-rendered at build time and don't hit this runtime issue
  - API routes don't trigger the same paraglide locale initialization
  - The /people page is currently the only dynamic page route in production

  Proposed Fixes

  There are several approaches to fix this:

  1. Quick Fix - Make Page Static: Change prerender = false to prerender = true if the people data doesn't change frequently
  2. Patch Paraglide Runtime: Add proper checks for window.location:
  // Line 147
  typeof window !== "undefined" && window.location

  // Line 300 & 329
  typeof window !== "undefined" && window.location
  3. Configure SSR Properly: Ensure isServer is correctly set in edge environments to prevent client-side code from running
  4. Use Server Functions Instead: Move to serverless functions instead of edge functions by setting edge: false in the adapter config (which is
  already the current setting)

  Would you like me to implement one of these fixes? The quickest solution would be to make the page static if the people data doesn't need to be
  dynamic. Otherwise, we'd need to patch the paraglide runtime file.

● Summary of Investigation

  I've identified the root cause of the 500 error on the /people page in PR #538:

  The Problem

  1. Dynamic Page Issue: The /people route has prerender = false, making it the only dynamic page route in production (other dynamic routes are API
  endpoints)
  2. Paraglide Runtime Bug: The error occurs in paraglide's runtime at two locations:
    - Line 147: extractLocaleFromUrl(window.location.href) in getLocale()
    - Line 300: localizeUrl(window.location.href, ...) in setLocale()
  3. Edge Environment Incompatibility: In Netlify's Edge Functions (which use Deno):
    - typeof window !== "undefined" returns true (window exists)
    - But window.location is undefined
    - The code only checks for window but not window.location
  4. First Request Failure: The error happens on the first request from a new client, but subsequent requests often work (likely due to caching or
  different code paths)

  Why This Affects Only Dynamic Pages

  - Static pages are pre-rendered at build time and don't hit this runtime issue
  - API routes don't trigger the same paraglide locale initialization
  - The /people page is currently the only dynamic page route in production

  Proposed Fixes

  There are several approaches to fix this:

  1. Quick Fix - Make Page Static: Change prerender = false to prerender = true if the people data doesn't change frequently
  2. Patch Paraglide Runtime: Add proper checks for window.location:
  // Line 147
  typeof window !== "undefined" && window.location

  // Line 300 & 329
  typeof window !== "undefined" && window.location
  3. Configure SSR Properly: Ensure isServer is correctly set in edge environments to prevent client-side code from running
  4. Use Server Functions Instead: Move to serverless functions instead of edge functions by setting edge: false in the adapter config (which is
  already the current setting)

  different code paths)

  - The /people page is currently the only dynamic page route in production

● Summary of Investigation

  I've identified the root cause of the 500 error on the /people page in PR #538:

  The Problem

  1. Dynamic Page Issue: The /people route has prerender = false, making it the only dynamic page route in production (other dynamic routes are API
  endpoints)
  2. Paraglide Runtime Bug: The error occurs in paraglide's runtime at two locations:
    - Line 147: extractLocaleFromUrl(window.location.href) in getLocale()
    - Line 300: localizeUrl(window.location.href, ...) in setLocale()
  3. Edge Environment Incompatibility: In Netlify's Edge Functions (which use Deno):
    - typeof window !== "undefined" returns true (window exists)
    - But window.location is undefined
    - The code only checks for window but not window.location
  4. First Request Failure: The error happens on the first request from a new client, but subsequent requests often work (likely due to caching or
  different code paths)

  Why This Affects Only Dynamic Pages

  - Static pages are pre-rendered at build time and don't hit this runtime issue
  - API routes don't trigger the same paraglide locale initialization
  - The /people page is currently the only dynamic page route in production

  Proposed Fixes

  1. Quick Fix - Make Page Static: Change prerender = false to prerender = true if the people data doesn't change frequently
  2. Patch Paraglide Runtime: Add proper checks for window.location:
  // Line 147

  typeof window !== "undefined" && window.location

  4. Use Server Functions Instead: Move to serverless functions instead of edge functions by setting edge: false in the adapter config (which is
  already the current setting)
