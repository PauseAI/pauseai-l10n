   - Records current status (e.g., `approved`)
   - Sets status to `pending` (triggers webhook, but ingestor ignores pending)
   - Sets status back to original (triggers webhook, ingestor processes if approved)
3. Waits `delay` seconds between API calls (rate limiting)

**The webhook trigger mechanism:**
Cloudinary fires a moderation webhook whenever status changes. By toggling `approved → pending → approved`, we get two webhooks - the second one (back to approved) is what the ingestor processes.

**What I was proposing:**
Add a `--since YYYY-MM-DD` flag that modifies the search expression to `asset_folder=sayno AND updated_at>2025-11-04`. This filters at the Cloudinary query level, so we only fetch and toggle the recently-changed images.

**Uncertainty:** Whether `updated_at` is the right field. Could also be `uploaded_at` for new uploads, or there might be a moderation-specific timestamp. Worth testing the query first before committing to the implementation.
