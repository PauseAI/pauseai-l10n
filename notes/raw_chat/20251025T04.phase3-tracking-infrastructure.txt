  Tracking Endpoints

  1. Open Tracking Pixel

  URL: https://collagen.pauseai.info/t/{uid}/open/{build_id}.jpg

  Lambda behavior:
  1. Extract uid, build_id from path
  2. Enqueue to SQS: {"event_type": "open", "uid": uid, "build_id": build_id}
  3. Return 302 redirect to actual 1024.jpg (pre-signed S3 URL or CloudFront)

  EC2 worker:
  1. Poll SQS for open events
  2. Query tracking.db for uid
  3. If opened_at is NULL: UPDATE users SET opened_at = NOW() WHERE uid = ?
  4. Log: "OPENED uid={uid} build_id={build_id} (idempotent)"

  Why 302 redirect:
  - Lambda doesn't need EFS mount (faster, cheaper)
  - Image served from S3/CloudFront (better performance)
  - Tracking happens async in background

  2. Opt-in Endpoint

  URL: https://collagen.pauseai.info/t/{uid}/opt-in

  1. Poll SQS for opt_in events
  2. Query tracking.db for uid → get email

    - UPDATE users SET validated_at = NOW(), subscribed_at = NOW() WHERE uid = ?
  4. Log: "OPTED_IN uid={uid} email={email} (idempotent)"

  4. Log: "OPTED_OUT uid={uid} email={email} (idempotent)"

  # Pseudocode for worker
  def handle_open_event(uid, build_id):
      user = db.get_user(uid)
      if user.opened_at is None:

          log.debug(f"OPENED (duplicate) uid={uid} build_id={build_id}")

      if user.subscribed_at is None:
          substack.subscribe(user.email)

> And the value really does end with a period? 

● Yes! The trailing period is important - it indicates a Fully Qualified Domain Name (FQDN) and tells DNS "this is the complete, absolute domain
  name, don't append anything to it."

  Without the trailing period, some DNS systems might append the zone name, turning:
  _3952831ec481eaf3b8dc226d4a040263.xlfgrmvvlj.acm-validations.aws

  into:
  _3952831ec481eaf3b8dc226d4a040263.xlfgrmvvlj.acm-validations.aws.pauseai.info

  Which would be wrong.

  However, Cloudflare's UI is smart about this - you can usually enter it either way:
  - With period: _3952831ec481eaf3b8dc226d4a040263.xlfgrmvvlj.acm-validations.aws.
  - Without period: _3952831ec481eaf3b8dc226d4a040263.xlfgrmvvlj.acm-validations.aws

  Cloudflare will typically handle it correctly. If in doubt, try without the trailing period first - Cloudflare's UI should accept it and internally
   treat it as an FQDN.
