## Problem

Netlify's Deno 2.3.1 edge runtime provides partial `window` object where `window` exists but `window.location` is undefined. This breaks paraglide-js assumptions, causing HTTP 500 on cold edge function starts.

Investigation documented in: `notes/20251113-paraglide-edge-function-investigation.md`

## Solution Approach

After exploring multiple options (post-compilation patching, pre-compilation patching, forking paraglide), chose **runtime window workaround**:

**Key Decision:** Delete incomplete window stub before paraglide loads, making Netlify Deno behave like standard Deno/Node.js.

### Implementation

**File:** `src/hooks.server.ts`
```typescript
declare const Deno: unknown
if (typeof Deno !== 'undefined' && typeof window !== 'undefined' && typeof window.location === 'undefined') {
    delete (globalThis as { window?: Window }).window
}
```

**Safety measures:**
- Triple condition prevents deletion in wrong contexts
- Deno check ensures browser window never deleted
- TypeScript `declare` has no runtime impact

**Configuration:** `scripts/inlang-settings.ts`
- Removed custom `isServer` override
- Now uses paraglide default: `typeof window === 'undefined'`
- Kept `disableAsyncLocalStorage: true` (correct for serverless environments)

## Technical Notes

**Why this approach works:**
- Executes before paraglide imports in `hooks.server.ts`
- Makes `isServer = typeof window === 'undefined'` evaluate to `true`
- Prevents all window.location access paths in paraglide
- No impact on browser code (Deno doesn't exist there)

**Alternative approaches rejected:**
- Adding window.location properties: More complex, risks affecting isServer evaluation
- Post-compilation patching: Fragile, maintenance burden
- Forking paraglide: Overkill for this use case
