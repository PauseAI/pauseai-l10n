## Summary

Implemented complete tracking infrastructure for Phase 3 email notifications. Built end-to-end system from API Gateway through Lambda/SQS to EC2 worker, with SQLite tracking database. All components deployed, tested, and verified working with real collage data.

## Completed

### Core Infrastructure

**Tracking Database (SQLite)**
- Schema: `users` table (uid, email, timestamps) + `collages` table (participation records)
- TrackingDB library (`lib/tracking.py`) with UID generation (8-char base58)
- Methods: `record_participation()`, `mark_emailed()`, `mark_opened()`, `mark_validated()`, `mark_subscribed()`
- Proper idempotency: all timestamp fields write-once
- Email uniqueness enforced via UNIQUE constraint

**S3 Storage**
- Bucket: `pauseai-collagen` (public-read)
- Upload script: `scripts/upload_collage_to_s3.py`
- Uploads both `{campaign}/{build_id}/1024.jpg` and `{campaign}/latest/1024.jpg`
- Production sayno collage uploaded: 266 images

**API Gateway + Lambda**
- Custom domain: `collagen.pauseai.info`
- ACM certificate validated, DNS configured in Cloudflare
- Lambda: `collagen-tracking-router`
- Routes: `/t/{campaign}/{uid}/{build_id}.jpg`, `/t/{campaign}/{uid}/validate`, `/t/{campaign}/{uid}/subscribe`
- Enqueues events to SQS, redirects users appropriately
- Campaign mapping: `test_prototype` → `sayno` for website display

**SQS Queue**
- Queue: `collagen-tracking-queue`
- 14-day retention, 60s visibility timeout
- Messages contain URL path for worker parsing

**EC2 Worker**
- Service: `collagen-tracking-worker` (systemd)
- Polls SQS via long polling (20s)
- Updates tracking.db based on event type
- Graceful unknown UID handling (warnings)
- Deployed and running on EC2

## Decisions Made

1. **Email uniqueness at tracking level**: SQLite UNIQUE constraint on email, `record_participation()` reuses UID for duplicate emails but adds multiple collage entries
2. **Campaign mapping in Lambda**: `test_prototype` displays as `sayno` on website (dev convention)
3. **Idempotent updates**: All `mark_*()` methods use `WHERE field IS NULL` to prevent overwriting timestamps
4. **UID format**: 8-char base58 (excludes ambiguous chars: 0O1Il)
5. **SQS message format**: Simple `{path, timestamp}` - let worker parse path
6. **Tracking pixel returns actual image**: Lambda redirects to S3, user sees 1024.jpg collage

## Technical Details

**URL Structure**
- Tracking pixel: `https://collagen.pauseai.info/t/{campaign}/{uid}/{build_id}.jpg`
- Validate: `https://collagen.pauseai.info/t/{campaign}/{uid}/validate`
- Subscribe: `https://collagen.pauseai.info/t/{campaign}/{uid}/subscribe`

**Redirect Destinations**
- Open → S3 image URL
- Validate → `https://pauseai.info/{display_campaign}?collagen_uid_{campaign}={uid}`
- Subscribe → `https://pauseai.info/join?collagen_uid_{campaign}={uid}`

**Query Parameters**
- Campaign-aware: `collagen_uid_{campaign}={uid}` for future cookie support
- Website will set cookies for personalization (future feature)
