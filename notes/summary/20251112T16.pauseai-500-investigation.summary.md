# PauseAI Website 500 Error Investigation
## 2025-11-12 Session

### Issue Context
PR #538 introduced a dynamic `/people` page that intermittently returns HTTP 500 on first access, particularly affecting new visitors. Subsequent requests typically succeed.

### Investigation Approach
1. Analyzed the people page implementation and its dynamic rendering configuration
2. Compared behavior across different runtime environments (Node.js vs Deno edge functions)
3. Tested with various tools to isolate caching vs initialization issues
4. Successfully reproduced the error with controlled experiments

### Key Findings

#### Confirmed Behaviors
- **First request to cold edge function returns HTTP 500** (takes ~6 seconds before failing)
- **Subsequent requests return HTTP 200** (take ~4-5 seconds for cache misses, ~0.6s for cache hits)
- **Edge function warm state persists** across multiple requests regardless of User-Agent
- **Netlify Edge caches by User-Agent header** with 3600-second TTL
- **Multiple edge instances can exist** - overlapping requests can trigger multiple 500 errors

#### Runtime Environment Differences
| Environment | Runtime | `/people` Behavior |
|------------|---------|-------------------|
| `pnpm preview` | Node.js | ✅ Always works |
| `netlify serve` (local) | Deno 2.2.4 | ✅ Works (30s cold, 5s warm) |
| Production Edge | Deno (version unknown) | ❌ First request fails with 500 |

#### Technical Analysis
The error occurs in paraglide's locale initialization during edge function cold start:
- Code checks `typeof window !== "undefined"` before accessing `window.location`
- Production Deno appears to have `window` defined but `window.location` undefined
- This assumption mismatch causes the runtime error
- Local Deno 2.2.4 does not exhibit this behavior (window is fully undefined)

### Speculation
- Production likely runs an older Deno version with different window object implementation
- Geographic distribution may affect which Deno version/configuration is encountered
- The issue could be specific to certain Netlify edge node configurations

### Current Status
- Problem definitively reproduced and understood
- Root cause identified in paraglide runtime initialization
- Workaround exists via caching (first visitor takes the hit, others benefit)

### Next Steps for Resolution
1. **Quick fix**: Set `prerender = true` for the people page (make it static)
2. **Runtime patch**: Modify paraglide to check `window.location` existence explicitly
3. **Configuration fix**: Investigate disabling edge functions for this route
4. **Long-term**: Wait for Netlify to update their Deno version
