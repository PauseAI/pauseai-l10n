## Investigation: How `desktop` flag is calculated

PR #579 adds a Table of Contents sidebar for wide viewports. The `desktop` boolean that controls this comes from the **svelte-toc library** (v0.5.9):

```
desktop = window.innerWidth > breakpoint
```

The PR sets `breakpoint={1250}`, so:
- `desktop === true` when viewport > 1250px → shows fixed left sidebar
- `desktop === false` when viewport ≤ 1250px → shows mobile popup button

## Terminology discussion

The codebase has three viewport zones:
- **Narrow** (≤600px): reduced spacing, hamburger menu
- **Middle** (601–1250px): full spacing, wide navbar, ToC as popup only
- **Wide** (>1250px): adds persistent ToC sidebar

The library's `desktop`/`mobile` naming is imprecise — it's really about viewport width, not device type. Suggested alternatives: `wide`/`notWide` or `sidebar`/`popup`. However, the library uses this terminology extensively in class names and CSS custom properties, so renaming in our wrapper would create a mismatch.

## Architecture question

The svelte-toc library has built-in desktop/sidebar support using `position: sticky` and CSS variables like `--toc-desktop-sticky-top`.

The PR instead:
1. Creates a separate `<div class="desktop-toc-wrapper">` with `position: fixed`
2. Renders a **second** `<Toc>` component inside it
3. Adds custom scroll tracking via `onMount` to adjust `top` dynamically
